# 口径与约定

改看板逻辑前先读这份。这里的口径都是踩过坑之后定下来的，改之前请确认是否真的要动。

所有逻辑都在 `build_final.py` 里，按 `§5.x` 编号分段，注释里写了原因。改前端表现改模板替换段，改数据口径改 `build_data.py` 的 SQL。

---

## 一、建议加推的三档门槛（锁定，2026-08-26 拍板）

轻故事沿用同一套标准，不单独降门槛。这是明知轻故事量级更小之后仍然保留的决定：用长篇标准量短篇，命中数会长期接近空白，但换来的是跨形态可比。

```js
// build_final.py §5.6 renderRecommendations
if (eff > 200) return true;                    // 有效在读 >200，其他指标不论，直接推
cnt = (eff>=100) + (ret>=25) + (rec>=80);      // 三项达标数
return cnt >= 2 && eff >= 50;                  // 任意两项达标即推，且有效在读≥50 兜底
```

| 档位 | 适用 | 条件 |
|---|---|---|
| 14 天内新书 · 建议加推 | 上架天数 ≤ 14 | 有效在读 >200；或（有效在读≥100 / 次留≥25% / 推荐值≥80% 满足任意两项，且有效在读≥50） |
| 老书优品 | 上架天数 > 14 | 有效在读≥300 且 次留≥30% 且 推荐值≥85% |
| 老书数据回春 | 上架天数 > 14 | 今日在飙升榜；或近 3 日有效在读较自身基线 ≥2.0 倍 |

已勾选加推的书仍然显示在列表里，只打「已加推」标记，不隐藏。

## 二、加推文案口径（2026-08-27 定）

- 文案里**不列具体数值**，只说哪些项符合 push 标准，例如「有效在读/推荐值符合push标准」
- **登上飙升榜必须注明**，例如「登上Top5」
- 数据明细表、展开依据面板里的数值是参考数据，不受此约束
- 弹窗 `dataStr` 与卡片 `buildReason` 是两处独立文案，改动要同步

## 三、飙升榜排名口径

- 数据源 `demo.toplist_event`，只取 `scene='rising'`
- 位次取 `argMax(index_of_page, stime)`，即**当日最后一次被记入时的位次**，接近当前位置
- 不能用 `min(index_of_page)`（当日峰值），那会把"当天到过的最高位"误当当前位
- 表内存在大量"陈旧位次残留"噪声：书掉榜后仍会留下极少量曝光记录，携带的却是掉榜前的位次。因此按位次分档设 UV 水位过滤：`rank≤5 → uv≥300`、`6~15 → uv≥200`、`16~30 → uv≥120`、`>30 → uv≥60`
- 某阅读平台没有对外开放的实时榜单接口，看板是**每日快照**，页面本身不联网

## 四、阅读总量口径（2026-10-16 加）

- 字段 `total_reading`，取自 `demo.book_meta`，含义为书籍累计阅读人数
- `demo.book_daily` 里没有这个字段，别找错表
- 链路：`build_data.py` 元数据 SQL → `extract.py` 的 `book.total_reading` → `build_final.py` §1 的 `metrics.total_reading`
- 前端三处：近期上线书籍概况表列、数据总览「阅读总量 Top 10」、分类分布维度（按一级分类求和）

## 五、分类口径

`demo.book_meta.category` 原始结构是**多条分类路径**：

```
一级:二级:三级;一级:二级:三级;...
```

分号分隔路径，冒号分隔级别。早期取数只取 `splitByChar(':')[1]/[2]`，即第一条路径的前两级，会丢掉真三级和其余路径。现在统一用 `fetch_category_full.py` 生成 `out/category_full.json`（bid → 三级全路径），`build_final.py` 合并为书籍字段 `category_full`，UI 读这个字段。

## 六、字段映射速查

| 看板显示 | 数据字段 |
|---|---|
| 有效在读 | `snap.eff_uv` / `metrics.effective_reading_uv` |
| 次留 | `snap.retain1` / `metrics.next_day_retention` |
| 推荐值 | `rec_rate` / `metrics.recommendation_rate` |
| 当日在读 | `snap.reading_uv` / `metrics.reading_uv` |
| 阅读总量 | `total_reading` / `metrics.total_reading` |
| 上架天数 | 由 `ondate` 与数据最新日期算 |

## 七、已知坑（别再踩）

1. **分类多路径**：见第五节，不要只取前两级或单条路径。
2. **榜单峰值回退**：若用 `<取数技能>` 取数，它产出峰值位次，`build_data.py` 必须在它之后跑，否则每日被覆盖回退。
3. **tPPT 10MB 单文件上限**：轻故事 1600+ 本的趋势数据是全表体积的大头，已裁剪到近 14 天并剔除 6 个恒零字段。扩大趋势窗口前先算体积。
4. **导出 CSV 静默崩溃**：19 本轻故事的 `metrics` 为 `null`，直接访问会抛 TypeError，表现为按钮点了没反应。已在导出函数里加零值兜底，不要删掉那行 `|| _emptyMet`。
5. **`byRec` 有两处同名定义**：`renderOverview`（看板卡片）和 `renderSmartOverviewAnalysis`（智能分析）各有一个。替换时锚点要带上 `.filter(b=>b.metrics.effective_reading_uv>=10)` 才能命中前者。
6. **观察期口径**：近期上线标记为「观察期」的判定是上架天数 ≤14，不是 7。
7. **加推排序键覆盖**：新书 Top 榜的下拉框只有指标项，点表头设置的排序键不能被下拉框值覆盖，否则「上架日期/上架天数」点了没反应。
