# 每日自动化 · 提示词原文

在 WorkBuddy 里新建「定时自动化」，把下面的提示词整段粘进去即可复现每日更新。

- 名称：某阅读平台出品书+轻故事每日监控与看板更新
- 频率：每天 11:00
- 工作目录：`weread_dashboard`（脚本里都是相对路径，工作目录必须指到这一层）
- 状态：ACTIVE

交接时把提示词里所有 `<工作目录>/...` 换成同事自己的路径。

部署站点名分两种情况：

- **接收方新建自己的站点**：`--site <新RTX>/weread-dashboard`
- **老站点已过户给她**：站点 URL 不变且永久带原负责人 RTX，此时部署命令**仍要写** `--site Annezhou/weread-dashboard`

另外，原负责人账号停用后，她名下的这条自动化自然停止执行。接收方必须在**自己的** WorkBuddy 里重建这条自动化，否则线上看板会停在最后一次部署的那天（静态页面不会自己更新）。

> 提示：现有原文只覆盖**出品书**的 BookID 增量同步，轻故事那一步需要用 `sync_sheet_ids.py` 补上，命令见文末「补充：轻故事同步」。

## 提示词原文

```
每日上午 11:00 执行某阅读平台 Annezhou 出品书单的监控与看板更新（无新增书时也照常刷新数据与重建看板，保证"每日更新"真正生效）。重要前提：必须用<企业协作平台>连接器 <表格读取工具> 读取，这是唯一可行的读表路径。

【A. 读表与增量判定（每日必跑）】
1. 确认 <表格读取工具> 可用并已授权：先 `<表格读取工具> --version`（需 ≥1.1.0），再 `<表格读取工具> auth show --status` 须为 authorized；否则停止并报错，不要伪造。
2. 取子表信息：`<表格读取工具> sheet get --json '{"docid":"[内部表格ID]"}'`，目标子表为 sheet_id=`[子表A]`（【出品ID190】长篇）。
3. 读子表数据（CSV）：`<表格读取工具> sheet ranges get --json '{"docid":"[内部表格ID]","sheet_id":"[子表A]","mode":"csv"}'`，返回 `content` 或 `file_path`，若是 file_path 用 read 工具读取该 CSV。
4. CSV 表头中 E 列=`*出品人`、U 列=`BookID`。筛选所有「*出品人」列值等于 Annezhou 的行，提取其 BookID（U 列），去重。
5. 读取 <工作目录>/weread_dashboard/ids.txt，与本次得到的 BookID 集合做差集，找出新增 bid。
6. 排除隐藏/跳过项：读取同目录 skip_bids.txt（每行一个 bid，不存在则跳过此步），凡出现在 skip_bids.txt 中的新增 bid 视为隐藏/不跟踪，不写入 ids.txt，仅在汇报中说明"已跳过隐藏 bid N 个"；其余真实新增 bid 追加写入 ids.txt（每行一个），并明确列出本次新增了哪些。

【B. 数据刷新（每日必跑，best-effort）】
7. 调用 <取数技能> 技能，按 ids.txt 全部 bid 重新抽取某阅读平台内部数据（元数据 / 天级阅读指标 / 榜单监测 / 新书检查长表），更新 weread_dashboard/out/dashboard_raw.json 与 dashboard_data.json。本步主要产出 dashboard_data.json（书籍指标/评级/books 列表）供 build_final.py 使用。
   - 前置依赖：<取数技能> 抽内部表需 VPN / 内网环境。若环境不可用导致抽取失败，不要伪造数据，在汇报中明确标注"本次数据未刷新（缺 VPN/内网）"，并继续往下执行第 9 步（用已有 JSON 重建看板，快照日标签仍反映上次成功抽取日期）。
7.5 运行 `python3 <工作目录>/weread_dashboard/build_data.py`，确定性重新生成 `out/dashboard_raw.json`。该脚本的榜单 toplist 查询用 `argMax(index_of_page, stime) AS latest_rank`（取当日最后一次被记入时的位次，即最接近当前的快照位次），取代 <取数技能> 输出里的 `min(index_of_page)` 峰值 `best_rank`，避免看板把"当天到过的最高位"误显示为当前位。build_final.py 优先读 dashboard_raw.json 的 toplist，故本步必须在第 7 步之后执行，否则会被 <取数技能> 的峰值口径覆盖回退。前置依赖同第 7 步（VPN/内网）；失败则标注"build_data 失败，榜单回退峰值口径"并继续。
7.6 运行 `python3 <工作目录>/weread_dashboard/fetch_category_full.py`，刷新 `out/category_full.json`（书籍「完整三级分类全路径」映射，覆盖 ids.txt + ids_qinggushi.txt 全量）。必要性：demo.book_meta.category 原始结构是「一级:二级:三级;一级:二级:三级;...」多路径，而 build_data.py 的 cat1/cat2 只取了第一条路径的前两级，会丢掉真三级和其余分类路径；看板的依据「分类」行与「表格行」都需要完整三级全路径。本步只查分类维表、开销很小，best-effort；失败则标注"分类映射未刷新，新书可能回退二级分类"并继续。
8. 调用 <新书追踪技能> 技能，对库内全部图书（尤其近 14 天新书）追踪最新表现数据。失败则标注并继续。

【C. 重建看板（每日必跑，无条件）】
9. 运行 <工作目录>/weread_dashboard/build_final.py，重新生成自包含看板 HTML。输出文件名固定为 数据看板_新版.html，每日覆盖更新同一份（不按日期新增文件）；快照日标签由数据最新日期自动生成；大标题为「Annezhou的数据看板」；保留浅色主题、新书核心指标 Top 榜、带勾选持久化的建议加推区（纯数据标准：达标新书 / 单项突出新书 / 老书优品 / 老书数据回春，不含任何热点关联）、数据小结置于近期上线板块下方且观察期 14 天。

【D. 部署到 tPPT（每日必跑，接在 C 之后）】
10. 将重建好的看板发布到 tPPT 内网站点，使线上页面与本地 HTML 同步更新。
    - 准备发布目录：`mkdir -p tppt_dist && cp "out/数据看板_新版.html" tppt_dist/index.html`（看板为单文件自包含，重命名为 index.html 让站点根路径直接打开）。
    - 执行部署：`python3 <技能目录>/tppt/tppt-deploy.py deploy --dir tppt_dist --site Annezhou/weread-dashboard --base-url https://[内部平台] --desc "每日自动更新 $(date +%F)"`。
    - 凭据已通过一次性 `login` 持久化在 `<部署凭据>`，部署命令静默读取，无需临时 PAT、无需人工介入。
    - 若部署失败（多为凭据过期，报错含 unauthorized / 401）：在汇报中标注"tPPT 部署失败（凭据可能过期）"，并提示用户重跑 `tppt-deploy.py login` 续期；不要反复重试阻塞。
    - 注意 tPPT 不保留历史版本，本步为整站替换，无法回滚。

完成后汇报：本次是否发现新增 bid、新增了哪些、是否有隐藏 bid 被跳过、数据是否成功刷新（或注明缺 VPN）、build_data 是否成功（榜单口径为最新位次或回退峰值）、分类映射是否刷新、看板更新到哪个文件、tPPT 部署是否成功（deployment_id 与线上 URL https://Annezhou.[内部平台]/weread-dashboard/）。
```

## 补充：轻故事同步（B 段第 7 步之前插入）

用脚本替代手工读表，参数化、可复用、幂等（重复跑不会写重复 bid）：

```bash
cd weread_dashboard
python3 sync_sheet_ids.py \
  --docid [内部表格ID] \
  --sheet-id [子表B] \
  --producer-col 出品人 --producer-val Annezhou \
  --bookid-col BookID --ids-file ids_qinggushi.txt --tag 轻故事

python3 build_data.py --ids ids_qinggushi.txt \
  --out out/dashboard_raw_qinggushi.json --tag 轻故事

python3 extract.py --raw out/dashboard_raw_qinggushi.json \
  --out out/dashboard_data_qinggushi.json --tag 轻故事
```

建议在自动化里把这段也写进去，否则轻故事的 BookID 不会随表格更新。

## 补充：完全不用 <取数技能> 的精简版

如果同事不想装技能，B 段可以整个换成脚本（包内 `deps/data_client.py` 已自带取数客户端）：

```bash
cd weread_dashboard
python3 sync_sheet_ids.py --docid [内部表格ID] --sheet-id [子表A] \
  --producer-col "*出品人" --producer-val Annezhou --bookid-col BookID --ids-file ids.txt --tag 出品书
python3 sync_sheet_ids.py --docid [内部表格ID] --sheet-id [子表B] \
  --producer-col 出品人 --producer-val Annezhou --bookid-col BookID --ids-file ids_qinggushi.txt --tag 轻故事
python3 build_data.py
python3 build_data.py --ids ids_qinggushi.txt --out out/dashboard_raw_qinggushi.json --tag 轻故事
python3 extract.py
python3 extract.py --raw out/dashboard_raw_qinggushi.json --out out/dashboard_data_qinggushi.json --tag 轻故事
python3 fetch_category_full.py
python3 build_final.py
```

这样榜单口径天然是最新位次，不存在峰值回退的问题。
